## rp-11 — Spreadsheet generation (`sheet_generate`)

**State:** code-complete, fixed, verified, **NOT committed**.

### What it does
Agent tool that writes a real `.xlsx` workbook with **live formulas** (written as
formula strings, not pre-computed values) to the conversation workspace, as a
DeliverableEvent artifact. Formulas are validated against a deny-by-default
whitelist. Frontend renders a `sheet` answer-block preview card.

### Defects I found in review (worker shipped these green)
1. **Host-side arbitrary file write (serious).** Tool declared `runs_in="sandbox"`
   but bypassed the sandbox: it called `openpyxl.wb.save()` directly to
   `ctx.workspace_path`, which is `"."` (the agent-server **host** cwd). With a
   model-controlled `filename`, that is an arbitrary host file write and `../`
   escapes the workspace. It also meant the artifact never landed in the
   conversation workspace, so the download path could not resolve.
   - **Fix:** render to an in-memory `BytesIO`, then write through
     `ctx.sandbox.write_file(...)` — jail-enforced (rejects `../`/absolute), lands
     in the workspace. Mirrors the existing `file_write` tool exactly.
2. **Whitelist bypass.** The formula deny-list regex anchored `(` immediately
   after the function name, so `=INDIRECT ("A1")` (space before paren) slipped
   past unchecked. Some spreadsheet engines tolerate that spacing.
   - **Fix:** regex now allows whitespace before `(` (`\s*\(`). Strictly
     fail-closed (only ever rejects more).
3. **False affordance (frontend).** `SheetBlock` had a Download button that always
   404s — there is no conversation id (`cid`) on the block render path, and the
   workspace-file endpoint only serves allowlisted images. 8 vitest tests "passed"
   only because they mocked `fetch`.
   - **Fix:** removed the button + its state + the error banner. The card is now an
     honest preview (title, filename, sheet badges, "saved to the workspace" +
     "formulas not evaluated" disclaimer). Real download stays on the
     deliverable-artifact flow (which holds the `cid`).

2. **Persisted depth/model_override are dead data.** The schedule row stores them

   before kicking (`set_model_override`/`set_depth`). And `_depth` is not persisted

   - **Fix needed:** apply `set_model_override(cid, sched.model_override)` and

## The `uv.lock` entanglement (blocks clean per-order commit)

because both orders ran in the same tree. The orchestrate commit gate stages only
manifest files, and a committed `uv.lock` must be internally consistent with the
committed `pyproject.toml` files. Committing one order's `uv.lock` as-is would leak
the other order's dependency.

   line) — rp-08's code stays on disk, only the dep line is removed.

3. Add `uv.lock` (+ the other missing files) to rp-11's manifest; commit rp-11.
4. Re-add `cronsim` to agent-server `pyproject.toml`; `uv lock` → `cronsim` back in.
5. After rp-08 is reviewed/verified, add `uv.lock` to its manifest; commit rp-08.

`frontend/package-lock.json` carries only rp-11's univerjs additions (rp-08's
frontend work adds no npm deps), so it is NOT entangled — it commits with rp-11.
